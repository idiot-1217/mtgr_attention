## 接口调用顺序

Python入口为`mtgr_ragged_segment_attention.py::mtgr_ragged_segment_attention`，参数名称和顺序与ACLNN业务参数相同，测试调用入口见`aclnn_backend.py`。C接口额外包含标准workspaceSize/executor/stream参数；`output_snd`由调用方分配。

推荐流程：准备NPU输入 → 独立AICPU metadata预处理 → attention主算子（一次主kernel launch）。metadata是设备INT32分核计划，决定section、可见块和各核任务范围，不是Host CPU模拟结果。

```python
from mtgr_ragged_segment_attention_metadata import MtgrMetadataHost
from mtgr_ragged_segment_attention import mtgr_ragged_segment_attention
# query等均为已准备的NPU Tensor；starts/prefixes/offsets/rules为INT32。
metadata = MtgrMetadataHost.prepare_metadata(
    q_seq_starts_i32, matched_prefix_lens_i32, segment_offsets_i32,
    l2_budget=l2_budget, rules=segment_rules_i32,
)
output = mtgr_ragged_segment_attention(
    query, key, value, segment_offsets_i32, segment_rules_i32,
    q_seq_starts_i32, matched_prefix_lens_i32, match_mode,
    key_cache, value_cache, block_table_i32, block_size,
    max_request_len, sm_scale, output_snd,
    block_M=128, core_num=32, num_stages=14, kv_group=kv_group,
    cross_interval=2, rule1_seg_idx=rule1_seg_idx,
    metadata=metadata, l2_budget=l2_budget,
)
```

ACLNN调用同样可传入上述已生成的metadata；Python测试桥`aclnn_backend.mtgr_ragged_segment_attention`保留相同业务参数。C/C++调用顺序：

1. `aclnnMtgrRaggedSegmentAttentionGetWorkspaceSize(全部23个业务参数, &workspaceSize, &executor)`创建执行计划；按workspaceSize分配workspace。
2. `aclnnMtgrRaggedSegmentAttention(workspace, workspaceSize, executor, stream)`在指定stream执行；读取输出前同步stream，完成后释放workspace与张量描述符。

若metadata传NULL/None，ACLNN executor会自动编排“独立AICPU metadata任务 → attention主kernel”，调用方不必另行预处理；GetWorkspaceSize只构造任务，实际AICPU在执行阶段运行。昨日全量、泛化和性能均使用此路径。提供metadata可复用计划，但输入分段、长度、GQA、核数、分块或L2预算变化后必须重新生成；跨stream复用须建立事件依赖。
